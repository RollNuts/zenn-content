# ブランチ整理の候補条件を試す、10件の合成テスト

[公開記事](https://zenn.dev/veripsa/articles/github-branch-cleanup-squash-556)の
`candidates`関数と、架空の入力だけを使う小さな再現例です。
GitHub APIへの接続、認証、実ブランチの参照・変更・削除は行いません。
実際のbranches/PR応答やバックアップbundleは含めていません。

## 実行

Python 3.12を使い、このREADMEと同じディレクトリで実行します。
標準ライブラリだけなので追加インストールは不要です。

```sh
python3.12 -m unittest -v
```

10件のtestメソッドが実行され、成功すると最後に `Ran 10 tests` と `OK` が表示されます。
一部のメソッドは `subTest` で複数の入力を確認します。

## 確かめる条件

| テスト | 確認すること |
| --- | --- |
| 1 | 待機期間を過ぎたmerged PRと現在のheadが一致すれば候補になる |
| 2 | マージ後にheadが進んだ枝は残す |
| 3 | 同じ枝にopen PRがあれば、古いmerged PRがあっても残す |
| 4 | 別forkの同名ブランチを一致としない |
| 5 | 対象repo内のopen PRのbaseとして使われる枝を残す（headがforkでも同じ） |
| 6 | 最近のマージと、閉じただけの未マージPRを残す |
| 7 | main、保護された枝、保護状態不明の枝を残す |
| 8 | 別のbaseへマージされた枝を残す |
| 9 | head repoが失われたPRと空入力を候補にしない |
| 10 | 入力のbranches/PR辞書を変更しない |

`branch_candidates.py`は候補を返すだけです。`test_branch_candidates.py`の
repo名・SHA・日時はすべて合成値です。

## この例の範囲

PRの確認範囲は、関数へ渡したPR snapshotだけです。記事の取得例は対象repoのPR一覧であり、
他repoやforkをbaseとするPRなど、あらゆる場所の利用状況を網羅するものではありません。
「入力にopen PRがない」ことを、全GitHubに利用中のPRがないことへ読み替えないでください。

このテストは、API取得の網羅性・snapshotの鮮度、現在のSHAや保護状態、
実行中のCI/commit checks、バックアップ・復元、削除直前の確認を自動化しません。
ref削除も実行しないため、GETとDELETEの間の競合を防ぐ仕組みではありません。
10件の成功は、これらの合成入力について候補条件が期待どおり働くという結果です。

実データを扱う場合の取得・レビュー・保持条件・復元確認・競合の限界は、元の記事を参照してください。

確認記録：2026-11-08、macOS / Python 3.12.13で上記コマンドを実行し、10件すべてOK・終了コード0でした。
