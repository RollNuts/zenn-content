AIでサイトを作って公開した。次に気になるのは「誰か見に来てくれたかな？」です。そこでAIに「アクセス数を表示して」と頼む前に、一つだけ決めておくと、あとで数字を読み違えずに済みます。

**記事を読んでいる途中でメールを確認し、元のタブに戻った。これも、もう1回に数えますか？**

個人で運営する「未発生新聞」の11月14日の集計は、サイト全体で81PVでした。この数字の単位はページが表示された回数です。同じ人が何度か開いても増えるので、何人が来たか、何人が最後まで読んだかは、この数字だけでは分かりません。[実際の日別集計](https://github.com/RollNuts/mihassei-news/blob/6843af3e3aff1ed791d02e4f9a236833c513245b/analytics/daily/2026-11-14.json)・[未発生新聞の数え方](https://veripsa.com/privacy/)

## メールから戻るのと、別のページから戻るのは同じ？

未発生新聞では、メールを見ただけなら記事の続きを読んでいると考えました。一方、別の記事まで読みに行ってから最初の記事に戻ったら、もう一度その記事を開いたと数えます。

| 読者がしたこと | ページの表示回数 |
| --- | --- |
| 裏のタブで記事を開き、そのままにした | まだ増えない |
| 開いておいたタブを初めて表示した | 1回増える |
| メールを確認し、開いたままのタブに戻った | 増えない |
| 別のページへ進み、ブラウザの「戻る」で記事を再表示した | 1回増える |

## AIには、頼みたい機能と一緒にこの場面を渡す

自分のサイトに付けるなら、たとえばこう頼めます。

> 記事が何回表示されたか知りたいです。記事を裏のタブで開いただけなら数えず、初めて表示したら1回。メールを見て同じタブに戻ったら追加0回。別のページから記事へ戻ったら追加1回にしてください。
>
> 本番の数字に混ぜずに試したいです。私がブラウザで行う操作と、そのつど画面に出るはずの数字を教えてください。

たとえば最初の表示でカウンターが10から11に変わったら、いったんメールを開いて記事に戻ります。そのあとも11なら、読みかけの記事を開き直した分は増えていません。**数字が増えてほしい場面と、増えたら困る場面を一つずつ渡す**と、コードが読めなくても、頼んだものができているかを自分で確かめられます。自分以外のアクセスが混ざらないローカルのプレビューで試すと、違いが見やすくなります。

## 「増えたら困る場面」は本当に役に立つか

執筆時にAIを使って、未発生新聞のプログラムのコピーを「タブが見えるたびに1回」と数えるように変え、テストを実行しました。メールから戻る場面で、ブラウザから送られる閲覧通知は、最初の表示と合わせて**期待は1件、実際は2件**。ほかの2件のテストは通りました。最初に記事を開いて「カウンターが動いた」と確認するだけなら、気づけない違いです。[タブを切り替えるテスト](https://github.com/RollNuts/mihassei-news/blob/6843af3e3aff1ed791d02e4f9a236833c513245b/tests/pageviews-ui.test.cjs#L211-L239)

:::details 実装を手元で確かめたい人へ
元の実装では、同じタブで記事を読み続けている間は一つの表示IDを使います。通信に失敗して再送するときも同じIDです。受け取る側では、そのIDを初めて受信したときだけ加算します。[ブラウザ側](https://github.com/RollNuts/mihassei-news/blob/6843af3e3aff1ed791d02e4f9a236833c513245b/assets/engagement.js#L800-L889)・[集計側](https://github.com/RollNuts/mihassei-news/blob/6843af3e3aff1ed791d02e4f9a236833c513245b/src/worker.js#L662-L709)

以下をmacOSやLinuxの空の作業用ディレクトリで実行すると、元のコードでタブ復帰・再送・受信側の重複処理を確かめられます。Node.js 22.16.0で3件すべて成功しました。テストはブラウザの操作を模擬し、集計にはメモリ上のSQLiteを使います。

```sh
base=https://raw.githubusercontent.com/RollNuts/mihassei-news/6843af3e3aff1ed791d02e4f9a236833c513245b
mkdir -p assets src tests
for file in assets/engagement.js src/worker.js tests/pageviews-ui.test.cjs tests/pageviews.test.cjs
do
  curl -fsSL "$base/$file" -o "$file" || exit 1
done
node --test \
  --test-name-pattern='only visible document displays count|a lost response retries|new page loads count PV' \
  tests/pageviews-ui.test.cjs tests/pageviews.test.cjs
```
:::

自分のサイトで本当に知りたいのが「この記事を読み終えた人がいるか」なら、AIへの最初の依頼も変わります。「アクセス数を出して」の手前にある、**その数字を見て何を知りたいか**から伝えてみてください。
